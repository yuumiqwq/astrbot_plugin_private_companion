# AstrBot shared conversation integration

Private sessions configured with AstrBot's `conversation_manager.shared_history` use the host conversation when composing proactive contacts and calendar plans. The integration calls `get_curr_conversation_id`, `get_conversation`, and `prepare_session_request`, so QQ synchronization and context compression follow the same host policy as ordinary replies. It does not make a separate QQ history request or apply the companion plugin's dialogue count and character limits to the imported host history.

The host verifies the selected role and supplies its current persona instruction and processed preset examples. Presets and saved dialogue use native user/assistant messages in the provider payload, including a native summary when compression produces one; they are not repeated inside the background material JSON. Ordinary dialogue from the plugin's observation store is replaced by the prepared host history. Delivery candidates remain available for duplicate detection. Hosts without the shared conversation interface retain the upstream behavior. Administrator diagnostics in a configured shared private session also use the current host persona and history, so their output can validate the same context integration as regular contacts.

Calendar planning uses the same preparation callback for daily, horizon, refinement, and conversation-triggered adjustments. An opted-in private window supplies its conversation background while the planner adds its calendar and planning task, retaining the existing JSON output contract and calendar persistence. Automatic planning for other windows retains the upstream role-wide scope. A failed history read prevents the planning request from silently proceeding with only its smaller local observation store.

Preparation happens before the model request budget check. Shared requests use AstrBot's token-based context policy instead of the adapter's fixed byte-estimate ceiling, which would otherwise reject many short QQ messages even when they fit the model context. The adapter counts the final wire and reserved output against the native model configuration or metadata, retains the fixed ceiling when that capacity is unavailable, and still reserves the full estimated cost. Other requests retain its byte ceiling. Shared background requests retain the current AstrBot persona instead of replacing it with the companion self-page profile. Other background tasks retain their upstream self-profile behavior, and proactive scheduling settings are unchanged.

For the same shared private sessions, proactive text also follows AstrBot's enabled regular-expression segmentation setting, while the companion plugin's own style rewriting and segmentation features remain disabled. A newline rule separates each nonempty line into a delivery, including single newlines and blank-line boundaries; short sentences on the same line remain together.

Expression comparison runs only when manually requested. It uses the complete approved AstrBot presets as its sole style target and new assistant replies since the last successful comparison as unreviewed comparison material. User messages provide context. Unreviewed replies do not provide positive style evidence. Candidates include exact approved quotations; concrete style patterns must occur in those quotations. Mixed comparison citations are reduced to approved learning evidence before a candidate is saved. Candidates remain pending until explicitly adopted.

The daily call retains `diary`, `day_plan`, `memory`, and `expression`, with scheduled expression output always null. The **立即对照学习** action runs comparison immediately; manual preview uses the same approved-only contract without saving candidates or progress. Successful candidate persistence and the durable QQ-sequence checkpoint advance together. Repeated manual runs without new replies do not call the model again. Clearing that checkpoint makes the next manual request inspect the available history again; later successful runs resume incremental processing.

The cottage's **学习与成长** page brings the manual comparison action and expression rule review into the **表达学习** workspace. Pending and adopted rules use the same rule list; approved dialogue examples remain managed by AstrBot. Native sample collection, source selection, daily self-review, behavior imitation, and the separate review center are retired. Growth proposals and their review remain in **成长链路**.

Semantic memory retrieval settings live in **事实与经历 → 记忆策略** at `#manage/memory/settings`. Group slang appears only when a group conversation is available. Older learning links resolve to the expression, growth, or memory workspace without restoring retired modules.
